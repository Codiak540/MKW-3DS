# Old 3DS engine performance: change log

Every change on branch `o3ds-engine-perf`, measured in the worktree's Azahar
copy (Old 3DS mode, unthrottled host speed) on the same scripted race: VS,
Mario / Standard Kart M, Luigi Circuit, 11 CPU racers, player CPU-driven for
1500 steps (`tools/o3ds_perf_verify.py`). Race frames are lockstep (two
simulation ticks per presented frame) so every build presents identical
frames.

Emulated ARM11 milliseconds count guest instructions; they are not hardware
time. Each change also passes the physics replay test (Funky Kong ghost,
Luigi Circuit, race timer and three lap splits, twice, identical heap) and an
identical per-racer CPU log (position, speed, rank, lap, items, AI state every
30 steps) against the baseline build.

Hardware model used for estimates (see docs/o3ds-perf-research-log.md): core 0
is fully available; the system core lends the application about 30% of its
time; hardware time is R times emulated time with R about 2.4–3.

### Extra checks on the final build (change 12)

- New 3DS mode (`is_new_3ds=true`): baseline vs final CPU log identical, 52/52
  captures pixel-identical; New 3DS keeps the render-thread layout. After
  change 14: 152/152 dense captures identical in New 3DS mode too (its
  render thread draws the recorded strip batches).
- The autopilot's built-in two-race script (Luigi Circuit with Standard Kart M,
  quit, Coconut Mall with Standard Bike M: bike `VehicleAnimation` paths,
  escalators, race restart): CPU log identical (864 lines), 44/44 captures
  pixel-identical. Its races end ~5 s after the countdown starts, before the
  layout calibration's 72 timing frames finish; full races finish
  calibrating during the countdown.
